# STANDARD OPERATING PROCEDURE (SOP) - PROJECT SENTINEL LOG INGESTION

## Document Code: SOP-SEC-2026-004
**Department**: Global Security Operations Center (GSOC)
**Author**: Neil Armstrong (Lead QA / SecOps Engineer)

## 1. Objective
To outline standard procedures for configuring and validating security event log forwarding from local applications to the centralized SIEM (Security Information and Event Management) platform.

## 2. Scope
Applies to all enterprise API microservices including Project Atlas, Project Aurora, and Project Helios.

## 3. Mandatory Log Metadata Fields
All security audit logs generated by microservices must contain:
1. `Timestamp` (ISO 8601 UTC format).
2. `UserPrincipal` (Validated JWT subject identifier).
3. `ClientIP` (Resolved remote client host IP).
4. `ActionType` (Standardized event categories: LOGIN_SUCCESS, DB_MUTATION, RBAC_VIOLATION).
5. `Status` (SUCCESS, ERROR, FORBIDDEN).

## 4. Ingestion Failover Procedures
If the SIEM collector endpoint fails to return an HTTP 200 OK status, the application must:
* Cache log events locally using a database write buffer (SQLite fallback table).
* Trigger automated notifications to SecOps on Duty after 10 consecutive connection failures.
* Restrict batch write size to 100 entries per post to avoid buffer overruns.
